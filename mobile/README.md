# Caimack для Android

Нативная оболочка вокруг того же сайта, что открывается в браузере. Своей сборки фронта внутри
нет: приложение — это WebView, которому при старте сказали открыть боевой домен.

Отсюда всё остальное. Правки во фронте доезжают до телефона сразу после деплоя, пересобирать APK
не нужно. Фронт и API остаются на одном origin, поэтому относительный `/api` и сессионные куки
работают ровно как в браузере, и ни строчки в `frontend/` менять не пришлось. Взамен приложение
бесполезно без сети и не умеет ничего, чего не умеет вкладка браузера.

## Что нужно для сборки

- **Node ≥ 22** — версия записана в `.node-version`, цели `make mobile-*` подставляют её через fnm.
- **JDK 21** — `sudo pacman -S jdk21-openjdk`.
- **Android SDK** с platform 36 и build-tools. Проще всего поставить Android Studio; из консоли —
  `cmdline-tools`, затем `sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"`.
  Путь к SDK нужен в `ANDROID_HOME` или в `android/local.properties` (`sdk.dir=/путь/к/Sdk`).

## Сборка

```bash
make mobile-install          # один раз
make mobile-apk              # APK в android/app/build/outputs/apk/debug/
```

Адрес берётся из `PUBLIC_DOMAIN` в корневом `.env`. Разово его можно переопределить:

```bash
MOBILE_SERVER_URL=https://music.example.com make mobile-apk
```

Установить на подключённый по USB телефон: `adb install -r <путь к apk>`.

Debug-сборка подписана отладочным ключом — её хватает, чтобы поставить приложение себе, но не
чтобы обновлять его поверх релизной или выкладывать куда-либо.

## Чего оболочка не делает

- **Не показывает управление на экране блокировки.** WebView, в отличие от браузера, не отдаёт
  системе Media Session — то есть `frontend/src/lib/useMediaSession.ts` внутри приложения молчит.
  Звук при свёрнутом приложении и погашенном экране продолжает играть, но паузу можно нажать
  только вернувшись в приложение, а без foreground-сервиса система вправе убить процесс.
- **Не работает офлайн.** Скачивание треков во фронте держится на service worker и Cache Storage;
  внутри оболочки они живут по обычным правилам сайта, поэтому загрузки не переживут ни очистку
  кэша, ни долгий простой. Настоящие офлайн-загрузки — это нативное хранилище, а значит
  вариант со сборкой внутри приложения.
- **Не годится для App Store.** Тонкий клиент над сайтом отклоняют по гайдлайну 4.2, да и сам
  `server.url` в документации Capacitor помечен как средство для live-reload, а не для прода.
  Google Play к такому терпимее, но и там это компромисс, а не финальная форма.

Каждый пункт снимается одинаково: сборка переезжает внутрь приложения, а плеер и загрузки
получают нативную реализацию. До тех пор это способ носить свою библиотеку в кармане, не трогая
фронт.
