# ADR-0008. UUIDv7 как идентификаторы

## Контекст

Каждой сущности нужен первичный ключ. Идентификаторы попадают в URL (`/api/tracks/{id}`), в ответы
API и в тела запросов от клиента.

## Варианты

1. **`int` / `bigint` с автоинкрементом.**
2. **UUIDv4** — случайный.
3. **UUIDv7** — упорядоченный по времени.

## Решение

**UUIDv7**, через `Guid.CreateVersion7()` прямо в инициализаторе свойства:

```csharp
public Guid Id { get; set; } = Guid.CreateVersion7();
```

**Против автоинкремента.** Последовательные числа в URL перечислимы: имея `/api/tracks/1`, можно
пройти всю библиотеку подбором. Для сервиса, где публичные плейлисты доступны по ссылке, это плохо.
Кроме того, идентификатор, назначаемый базой, недоступен до `SaveChangesAsync`, а он нужен раньше —
например, для вычисления пути файла в хранилище.

**Против UUIDv4.** Случайный UUID как первичный ключ фрагментирует B-tree: каждая вставка попадает в
случайное место индекса, страницы дробятся, кэш работает вхолостую. На таблице `playback_events`,
куда пишется поток событий, это ощутимо.

**За UUIDv7.** Старшие биты — метка времени, поэтому новые строки ложатся в конец индекса, как у
автоинкремента, но остаются непредсказуемыми. Плюс два побочных выигрыша:

- **сортировка по `Id` эквивалентна сортировке по времени создания** — это используется как
  дешёвый tie-breaker;
- **раскладка файлов в хранилище**: `FileSystemMusicStorage` строит путь вида `music/{xx}/{yy}/{uuid}`,
  разбирая последние байты GUID. У UUIDv7 они случайны, поэтому каталоги наполняются равномерно, и
  ни в одном не оказывается десятков тысяч файлов.

Отдельно: `PlaybackEvent` имеет **и** `Id` (UUIDv7), **и** `Sequence` (identity базы). Это не
избыточность — `Sequence` служит watermark для возобновляемого роллапа, и для этого нужен именно
монотонный серверный счётчик, см. [ADR-0022](0022-droppable-telemetry.md).

## Последствия

**Получаем:**
- Идентификатор известен до сохранения.
- Локальность вставки в индексе.
- Неперечислимые URL.
- Бесплатный порядок «по времени создания».

**Платим:**
- 16 байт вместо 8 — во всех индексах и внешних ключах. Для библиотеки в десятки тысяч треков это
  несущественно.
- В URL идентификатор длинный и нечитаемый.
- Метка времени в UUIDv7 не секретна: по идентификатору видно, когда объект создан.

## Когда пересматривать

Не планируется. Смена типа первичного ключа задним числом потребовала бы миграции всех таблиц и
всех внешних ключей.
