# Записи об архитектурных решениях

Каждый файл здесь описывает **одно** решение по единому шаблону:

- **Контекст** — какая задача стояла и в каких условиях;
- **Варианты** — что рассматривалось;
- **Решение** — что выбрано;
- **Последствия** — что мы за это получили и чем платим;
- **Когда пересматривать** — при каких условиях выбор перестанет быть верным.

Решения записаны задним числом, по коду: они не предваряли разработку, а извлечены из неё. Поэтому
раздел «Варианты» — это реальные альтернативы, а не протокол совещания.

## Правила работы с записями

1. **Записи не переписывают.** Если решение изменилось — заводится новая запись со ссылкой
   «Заменяет NNNN», а в старой появляется строка «Заменено на NNNN». Ценность архива в том, что по
   нему видно, почему когда-то сделали иначе.
2. **Ссылаться, а не пересказывать.** В обычных главах должно стоять «см. ADR-NNNN», а не копия
   обоснования: копия разойдётся с оригиналом.
3. **Новое решение — новая запись.** Если в PR вы отказываетесь от библиотеки, меняете модель
   согласованности или вводите новое ограничение развёртывания — это запись, а не строка в описании
   PR.
