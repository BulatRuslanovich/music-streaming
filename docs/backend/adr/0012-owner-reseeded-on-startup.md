# ADR-0012. Владелец восстанавливается в правах на каждом старте

## Контекст

Регистрации в приложении нет: учётные записи заводит администратор. Значит, первая учётная запись
должна появиться откуда-то ещё. Кроме того, администратор может по ошибке снять с себя права или
деактивировать собственную запись — и тогда войти станет некому.

## Варианты

1. **Создать владельца один раз** при пустой базе и больше не трогать.
2. **Отдельная CLI-команда** восстановления доступа.
3. **Создавать при отсутствии и восстанавливать права на каждом старте.**

## Решение

Вариант **3**.
[`DatabaseInitializer.SeedOwnerAsync`](../../../backend/src/MusicStreaming.Infrastructure/Persistence/DatabaseInitializer.cs)
на каждом запуске:

1. ищет пользователя с именем `Owner:Username`;
2. если его нет — **создаёт** его администратором (требуя `Owner:Password` длиной не менее 8 символов,
   иначе падает с внятным сообщением);
3. если он есть, но лишён прав или деактивирован — **возвращает** `IsAdmin` и `IsActive`;
4. если задан `Owner:ResetPasswordOnStartup=true` — **сбрасывает пароль** из настроек.

```csharp
// Учётная запись владельца всегда возвращается действующим администратором: это
// единственный путь назад, если администраторы заперли сами себя.
if (!existing.IsAdmin || !existing.IsActive)
{
    existing.IsAdmin = true;
    existing.IsActive = true;
    …
}
```

**Против варианта 1.** Он оставляет систему без выхода из состояния «все администраторы потеряли
доступ». В self-hosted приложении помочь некому: нет поддержки, которая зайдёт в базу.

**Против варианта 2.** Отдельная команда требует и отдельного образа, и знания о её существовании в
тот момент, когда человек уже не может войти. Восстановление, привязанное к перезапуску, работает без
предварительных знаний: «поправьте `.env`, перезапустите контейнер» — инструкция, которую можно дать
кому угодно.

Разделение сброса пароля отдельным флагом важно: восстановление **прав** безопасно и происходит
всегда, а вот пароль трогать без явного разрешения нельзя — иначе он возвращался бы к значению из
`.env` при каждом перезапуске, обесценивая любую смену пароля.

## Последствия

**Получаем:**
- Гарантированный выход из самоблокировки.
- Первичная настройка не требует ручных действий с базой.
- Сброс пароля — управляемый и явный.

**Платим:**
- **Учётную запись владельца нельзя отключить насовсем.** Деактивация продержится до ближайшего
  перезапуска. Это нужно знать: если владельца хотят вывести из эксплуатации, сначала меняют
  `Owner:Username` на другого пользователя.
- Кто угодно, имеющий доступ к `.env` и возможность перезапустить контейнер, получает доступ к
  приложению. Это осознанно: обладание файлом окружения и правом перезапуска и так означает полный
  контроль над сервером.
- Забытый `Owner:ResetPasswordOnStartup=true` будет молча возвращать пароль при каждом старте.
  В логи при этом пишется предупреждение — стоит на него смотреть.

## Когда пересматривать

Если появится многопользовательский сценарий с внешним поставщиком удостоверений (OIDC) — тогда
владелец в базе перестанет быть последней линией обороны.
