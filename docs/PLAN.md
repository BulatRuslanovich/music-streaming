# План доработок

Что взять из musik: подключение существующей музыки, рекомендации, аккаунты и безопасность,
развёртывание, дубликаты по chromaprint, LUFS/BPM/тональность в каталоге.

## Исходные наблюдения

- **Миграций нет.** `db/init` срабатывает только на пустой базе, а почти каждый пункт ниже
  меняет схему. Поэтому этап 0 — механизм миграций.
- **Анализ уже декодирует каждый трек целиком один раз** (`backend/crates/media/src/analysis.rs`,
  symphonia). Chromaprint, LUFS и тональность считаются в том же проходе, без fpcalc и второго
  декодирования. BPM уже считается (`track_cues.tempo_bpm`), но в каталоге не виден.
- **Внешнюю библиотеку подключить почти даром.** `file_path` — путь относительно `STORAGE_ROOT`,
  стриминг, HLS и анализ берут файл через `storage.existing()`. Если смонтировать папку пользователя
  как `/storage/library` (только чтение), остальной код работает как есть.

## Принятые решения

- Нормализация громкости **выключена по умолчанию**, включается в настройках воспроизведения,
  как кроссфейд.
- Загруженные через интерфейс файлы, как и сейчас, пишутся в `storage/music`. Внешняя библиотека
  монтируется только на чтение.
- SQLite не поддерживаем: бэкенд построен на Postgres (`gin_trgm_ops`, `sqlx::query!` с проверкой
  на этапе компиляции, `PgPool` повсюду), а Postgres в compose пользователю ничего не стоит.
- Несколько профилей вкуса на один аккаунт не делаем: при приглашениях дешевле второй аккаунт.

## Этап 0. Фундамент: миграции и быстрые правки безопасности

### 0.1 Миграции схемы

- [x] Текущий `db/init/*.sql` → `db/migrations/0001_baseline.sql`, до первого релиза схема правится прямо в нём, без новых файлов.
- [x] Подкоманда `caimack migrate` (рядом с `caimack healthcheck`) через `sqlx::migrate!`.
- [x] Существующие установки: если таблицы есть, а `_sqlx_migrations` нет — базовая версия
      помечается применённой без выполнения.
- [x] Принцип «бэкенд не мигрирует» сохраняется: `serve` только сверяет версию схемы и с понятной
      ошибкой отказывается стартовать при несовпадении.
- [x] Одноразовый сервис `migrate` в compose; `backend` зависит от него через
      `service_completed_successfully`.
- [x] CI: вместо цикла `psql` по `db/init` — `caimack migrate`.
- [x] Обновить `db/README.md`.

### 0.2 Быстрые правки безопасности

- [x] **Ограничение попыток входа** в `/api/auth/login` (`backend/crates/app/src/auth/mod.rs`):
      отдельно по IP (через `ClientInfo`, там уже учитываются `TRUSTED_PROXIES`) и по имени
      пользователя: 5 неудач в минуту на имя, 20 на адрес, ответ `429` с `Retry-After`. Счётчик
      в памяти (`backend/crates/app/src/auth/throttle.rs`).
      То же для `me/password` (по пользователю). `refresh` не ограничиваем: токен — 256 случайных
      бит, подбирать нечего, а лимит только мешал бы Android обновлять сессию.
- [x] **CSRF.** Сессия в cookie с `SameSite=Lax` (`backend/crates/api/src/auth.rs`). Middleware:
      для POST/PUT/PATCH/DELETE браузер должен сообщить `Sec-Fetch-Site: same-origin`/`none`,
      а без него `Origin` должен совпадать с `Host` (`backend/crates/api/src/csrf.rs`). Клиенты
      без браузера (Android, curl) таких заголовков не шлют и проходят.

## Этап 1. Анализатор v2: chromaprint, LUFS, тональность

Всё — в том же проходе в `backend/crates/media/src/analysis.rs`, что CLAP и точки склейки.

| Что | Как | Хранение |
|---|---|---|
| Chromaprint | `rusty-chromaprint` (чистый Rust), моно 11025 Гц, первые 120 с | `track_fingerprints(track_id, fingerprint int4[])` |
| LUFS | `ebur128`: integrated loudness, true peak, LRA | `track_cues`: `loudness_lufs`, `true_peak_db`, `loudness_range_lu` |
| Тональность | своя реализация на `realfft`: хромаграмма → профили Krumhansl–Kessler, 24 тональности + уверенность | `track_cues`: `musical_key` (0..23), `key_confidence` |
| BPM | уже был | `cues.bpm` в `TrackDto` |

- [x] `cues::VERSION` = 3 — фоновый воркер сам пересчитает библиотеку. CLAP при этом не пересчитывается,
      если эмбеддинг свежий.
- [x] `key` (тоника, мажор/минор, Camelot) и `loudness` в `TrackDto`; сортировки `bpm`/`key`/`loudness`
      и фильтры `bpmMin`, `bpmMax`, `key` (Camelot, через запятую) в `/api/tracks`; колонка «BPM · Тон»,
      сортировки и фильтры на странице треков; строка «BPM · тональность · LUFS» в карточке трека на Android.
- [x] Нормализация громкости: только приглушение до −18 LUFS через громкость элемента/плеера (без
      `GainNode` и лимитера — громче 1.0 не поднимаем, поэтому true peak не нужен). Веб — с учётом
      кроссфейда, Android — вместе с таймером сна. **Выключена по умолчанию**, переключатель рядом
      с умными переходами.
- [ ] BPM и тональность — признаки для переходов и радио (этап 4.3).

## Этап 2. Дубликаты на chromaprint вместо CLAP

Порядок проверки (`backend/crates/reco/src/duplicates.rs`):

1. **Точная копия** — совпадает `content_hash` (уже гарантирует уникальный индекс).
2. **Chromaprint** — пары с длительностью в пределах ±3 с / 3%. Кандидаты — из индекса по каждому
   восьмому (по хешу) значению отпечатка и из совпадения тегов; отпечатки выравниваются со сдвигом
   до ±32 элементов (~4 с). Доля несовпадающих бит ≤ 0.2 — один и тот же звук. На своей библиотеке:
   копии 0.003–0.02, разные треки не ниже 0.39.
3. **Метаданные** — только если у одного из треков нет отпечатка: тот же `song_key` и длительность.
   При отпечатках у обоих решает звук: одинаковые теги с разным звуком — не дубликаты.

- [x] Пороги CLAP (`SOUND_ALIKE*`) удалены; поиск больше не зависит от эмбеддингов.
- [x] `duplicate_dismissals`, `merge_duplicates` и `best_first` без изменений (FLAC и так идёт
      первым: принимаются только MP3 и FLAC).
- [x] Совпадения кешируются (`recommendations/sound.rs`) и пересчитываются, когда меняются треки
      или отпечатки: фоном раз в 10 минут или при открытии страницы. 50 тысяч записей — ~0.5 с.
- [x] Радио исключает клоны по звуку (`Snapshot::set_sound_alikes`), с учётом «это разные треки».
- [x] Группы только по тегам показываются как «Совпадают исполнитель и название».
- [x] Тесты: перекодированная и обрезанная копии в одной группе; одинаковые теги с разным звуком;
      без отпечатка решают теги; далёкие длительности; «разные треки»; слабейшее звено группы.

## Этап 3. Подключение существующей музыки

### Модель данных

- [x] Состояние сканера — в отдельной таблице `library_files` (путь, размер, mtime, хеш, трек, статус:
      связан / убран пользователем / пропущен / ошибка, `missing_since`). В `tracks` только видимые треки,
      поэтому 44 запроса к каталогу фильтровать не нужно; `origin` определяется по пути `library/…`.
- [x] `tracks.file_path`: `varchar(400)` → `text`.
- [x] Env `MUSIC_LIBRARY_PATH` (по умолчанию `./library`); в compose — `/storage/library:ro`.
- [x] Загрузки через интерфейс по-прежнему пишутся в `storage/music`.

### Сканер (`backend/crates/app/src/library_scan.rs`)

- [x] Обход через `walkdir` (по символическим ссылкам), только MP3/FLAC; m4a/ogg/opus/wav и т. п. —
      счётчик «формат не поддерживается»; скрытые папки и `._*` пропускаются.
- [x] Неизменённые файлы (путь, размер, mtime) пропускаются без чтения.
- [x] Новый файл: sha256 + теги через общий `Uploads::import` — тот же путь, что у загрузки
      (те же правила дублей и замены lossy на lossless).
- [x] Файл уже есть в каталоге (тот же хеш или lossless той же песни) — «уже в библиотеке».
- [x] **Переезд:** тот же хеш на новом пути — тот же трек, лайки и история на месте.
- [x] **Изменённый файл** (перетегирован снаружи): трек получает новый хеш и переанализируется,
      теги в каталоге не перезаписываются.
- [x] **Пропавший файл:** `missing_since`; через 30 дней трек удаляется. Если папка пуста целиком
      (диск не подключён) — ничего не помечается.
- [x] Обложка из папки альбома: `cover` / `folder` / `front` (.jpg/.jpeg/.png) важнее встроенной.

### Когда запускается

- [x] При старте и по расписанию (`LIBRARY_SCAN_INTERVAL_MINUTES`, по умолчанию 60, `0` — только вручную).
- [x] «Пересканировать» и прогресс — в разделе «Папка с музыкой» на странице загрузки
      (`GET`/`POST /api/library/scan`).
- [ ] `notify` (inotify) — не делал: опрос и кнопка покрывают сценарий, а на SMB/NFS и в Docker Desktop
      события всё равно не доходят.

### Защита пользовательских файлов

- [x] `Storage::delete` ничего не удаляет внутри `library/` — это закрывает удаление трека, слияние
      дубликатов и замену при загрузке. Тест есть.
- [x] Трек из папки, удалённый в приложении или при слиянии, помечается «убран пользователем» и не
      возвращается при следующих сканах, даже если файл временно пропадал.
- [x] Правка тегов меняет только базу (файлы пишет только импорт из Яндекс Музыки, в свои загрузки).

### Масштаб

- [ ] Загрузку индекса и карту на 50k треков не проверял: нет такой библиотеки. Сравнение по звуку
      на 50k — ~0.5 с (этап 2).

## Этап 4. Рекомендации

Не повторять musik целиком, а взять то, что окупается на одном домашнем сервере.

### 4.1 Достоверные данные

- [ ] Таблица `recommendation_impressions`: `id`, `user`, `request_id`, `track`, `source`,
      `position`, `explore`, `score`, `features jsonb` (с версией), `outcome`.
- [ ] Radio API отдаёт `impression_id` рядом с `RadioPick { explore }`; веб и Android передают его
      в `playback_events`.
- [ ] Исходы: `finished` / `partial` / `early_skip` / `superseded` / `abandoned`. Несыгранный трек
      негативом не считается.

### 4.2 Явное управление вкусом

- [ ] **Дизлайк.** Событие `TrackDismissed` уже есть — сделать из него постоянный отрицательный
      прототип в `backend/crates/reco/src/taste.rs`, отдельно от положительных мод, а не вычитанием.
- [ ] **Правила** `block` / `cooldown` / `downrank` для трека, артиста, альбома и жанра, с отменой.
      Отдельная таблица, с дизлайком не смешивается.
- [ ] **Радио от якоря** с кнопками «ближе» / «шире» и подписью источника («похоже на тебя»,
      «чуть в сторону»).

### 4.3 Единая оценка `w·x` и переходы

- [ ] Признаки: сходство с модами вкуса, новизна, давность, повтор артиста, популярность,
      переход A→B (близость BPM, совместимость тональностей по Camelot, разница громкости).
- [ ] Глобальный MMR по всей очереди вместо локальных штрафов.
- [ ] Детерминированные тесты на `Rng` + симулятор слушателя: «один вкус», «два вкуса»,
      «смена настроения», «устойчивый дизлайк».

### 4.4 Обучение весов (опционально)

- [ ] Логистическая регрессия по impression'ам с temporal holdout; новые веса принимаются, только
      если log-loss не хуже модели по умолчанию.
- На 1–5 слушателях порог в ~1500 размеченных impression'ов набирается месяцами. Thompson sampling —
  только после этого. Основная польза — в 4.1–4.3.

## Этап 6. Развёртывание и эксплуатация

- [ ] **Модель CLAP без PyTorch.** Готовый ONNX как release-артефакт с sha256; `caimack` при первом

      своими силами.
- [ ] **Готовые образы** в GHCR из CI и `docker-compose.images.yml` без сборки на сервере.
- [ ] **Скрипт установки** `setup.sh`: генерирует `POSTGRES_PASSWORD`, `JWT_SIGNING_KEY`,
      `OWNER_PASSWORD`, спрашивает домен и папку с музыкой, делает `docker compose up -d`.
- [ ] **Бэкапы:** `pg_dump` в `storage/backups` с ротацией + инструкция по восстановлению.
      Музыку и `hls/` в бэкап не включать (HLS пересоздаётся).
- [ ] **`docs/UPGRADE.md`:** «pull → migrate → up» и откат.
