# ADR-0018. Ленивое перекодирование с отдачей оригинала

## Контекст

Библиотека содержит файлы разных форматов: mp3, flac, aac, alac. Пользователю нужны ступени качества
(экономия трафика на мобильном интернете), а некоторые исходники браузер вовсе не умеет играть —
ALAC не поддерживают ни Chrome, ни Firefox.

Перекодирование одного трека занимает секунды, и держать слушателя всё это время нельзя.

## Варианты

1. **Перекодировать при загрузке**, сразу во все ступени.
2. **Перекодировать на лету**, отдавая поток из ffmpeg прямо в ответ.
3. **Перекодировать лениво**: при промахе кэша отдать оригинал и поставить задачу в очередь.

## Решение

Вариант **3**, в
[`StreamingService.OpenTrackAsync`](../../../backend/src/MusicStreaming.Application/Services/StreamingService.cs#L45-L103):

```csharp
if (wanted != AudioQuality.Original && transcoder.IsAvailable)
{
    var cached = storage.OpenRead(storage.TranscodePathFor(track.ContentHash, wanted));
    if (cached is not null)
        return /* перекодированный файл */;

    transcodeQueue.TryEnqueue(new TranscodeRequest(track.ContentHash, track.FilePath, wanted));
}

// кэша нет — отдаём оригинал прямо сейчас
```

Слушатель **всегда получает звук немедленно**. Первое включение трека придёт оригиналом, следующее —
уже в нужной ступени.

**Против варианта 1.** Загрузка альбома из 12 треков превратилась бы в 36 запусков ffmpeg (три
ступени), то есть в минуты ожидания. При этом большинство ступеней никто никогда не запросит: у
пользователя одна настройка качества.

**Против варианта 2.** Отдача из работающего ffmpeg несовместима с перемоткой: заранее неизвестна
длина, невозможны запросы по диапазонам, а каждая перемотка означала бы новый процесс. Плюс каждое
воспроизведение стоило бы процессорного времени, а не только первое.

## Сопутствующие детали

- **Ключ кэша — хеш содержимого**, а не идентификатор трека: `transcodes/{contentHash}-{quality}`.
  Правка тегов не инвалидирует перекодированный файл, потому что звук не изменился.
- **Целевой формат — Opus** (`-c:a libopus`, VBR). Лучшее качество на битрейт из широко
  поддерживаемых, играется всеми актуальными браузерами.
- **Атомарная запись**: результат пишется в `.part` и переименовывается. Прерванное перекодирование
  не оставит битый файл, который потом отдадут слушателю.
- **`-map_metadata -1`**: теги в перекодированную версию не переносятся. Она служебная, метаданные
  клиент берёт из API.
- **`-threads 1`**: одно перекодирование не должно занимать все ядра сервера, на котором идёт
  воспроизведение.
- **ffmpeg может отсутствовать.** `IsAvailable` проверяется один раз через `ffmpeg -version` и
  кэшируется в `Lazy<bool>`. Если бинарника нет, `ConfigController` просто не объявляет клиенту
  ступени качества, кроме `Original`, — приложение остаётся работоспособным.

## Последствия

**Получаем:**
- Отклик не зависит от ffmpeg.
- Перекодируется только то, что реально слушают.
- Отсутствие ffmpeg — деградация, а не отказ.

**Платим:**
- Первое воспроизведение идёт в исходном размере, то есть экономия трафика включается со второго
  раза. Для DataSaver это заметно.
- **Если исходник — ALAC, первое воспроизведение просто не заиграет**: браузер не умеет его
  декодировать. Второе — уже да. Это самое неприятное следствие решения.
- Кэш перекодирования растёт и сам не чистится.
- Очередь `TranscodeQueue` — в памяти: перезапуск теряет невыполненные задачи. Не страшно, задача
  будет поставлена заново при следующем воспроизведении.

## Когда пересматривать

Если ALAC и другие неиграбельные форматы станут заметной долей библиотеки — их стоит перекодировать
сразу при загрузке, оставив ленивую схему только для ступеней качества.
